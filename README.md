# Дневник давления Omron

Android 8+ → фото экрана → существующая Ollama → проверка трёх чисел → база сервера → Google Таблица.

## Архитектура

Отдельная Ubuntu 24.04 VM в Proxmox хранит измерения в SQLite, обслуживает Android API и синхронизирует Google Таблицу. Начальный размер: 2 vCPU, 2 ГБ RAM, диск 20 ГБ. Модель работает на существующем AI-сервере: проект **не устанавливает и не запускает Ollama**.

В Android доступны камера, выбор фото, ручная корректировка, сохранение, последние 50 измерений и средние за 30 дней. Все записи доступны через API с пагинацией. Веб-интерфейс и Android показывают графики, выбор периода, журнал, CSV и печатный отчёт для врача. Редактирование сохранённых записей пока не реализовано.

## Статус

Локальное сохранение и очередь проверены автоматическими тестами. Проверены распознавание реального фото через отдельный сервер, HTTPS и запись в Google с повтором после потери ответа без дубля. Перед использованием проверьте работу на своём телефоне. Публичный репозиторий содержит только исходники и примеры. Числа в тестах синтетические.

## Развёртывание на отдельной VM

1. Установите Docker Engine и Compose по [инструкции Docker для Ubuntu](https://docs.docker.com/engine/install/ubuntu/).
2. Клонируйте репозиторий и перейдите в его каталог.
3. Скопируйте `.env.example` в `.env`. Создайте `API_TOKEN`: `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`.
4. Укажите `OLLAMA_URL=http://АДРЕС_AI_СЕРВЕРА:11434`, `VISION_MODEL=gemma3:4b`, ID Google Таблицы и **новое отдельное имя вкладки**, например `Измерения`.
5. Настройте Google по следующему разделу. Для проверки локального API можно временно запустить только сервис `api` без Google-ключа.
6. `mkdir -p secrets` и `docker compose up -d --build`.
7. Проверьте `GET /health` с заголовком `Authorization: Bearer ВАШ_ТОКЕН` на порту 8000.
8. Настройте HTTPS reverse proxy на API. По умолчанию порт 8000 доступен внутри VM; если proxy находится в другой VM, укажите LAN IP приложения в `BIND_IP` и разрешите порт только для proxy.
9. В телефоне укажите HTTPS-адрес API с доверенным Android сертификатом и токен. Телефон подключается через домашнюю сеть или VPN.

Доступ API к Ollama разрешите только внутри домашней сети. Внешний порт Ollama не нужен. API не хранит фото на диске; снимок проходит через память API и существующей Ollama.

## Google Таблица для врача

1. В Google Cloud включите Sheets API, создайте service account без широких ролей в Cloud и JSON-ключ.
2. Положите ключ в `secrets/google.json`. Файл должен читаться UID 1000 внутри контейнера. На VM: `sudo chown 1000:1000 secrets/google.json && sudo chmod 600 secrets/google.json`.
3. Предоставьте `client_email` из ключа доступ редактора **только к нужной таблице**.
4. Укажите `SPREADSHEET_ID` и новое имя вкладки в `.env`. Начните с тестовой таблицы.
5. Синхронизатор создаст вкладку и видимые столбцы: **Дата, Время, Верхнее, Нижнее, Пульс, Примечание**. Технический ID хранится в скрытом столбце G.

Подтверждённое измерение сначала сохраняется в базе VM. Отдельный процесс каждые 60 секунд отправляет ожидающие строки в Google. Ошибка Google не отменяет запись в базе. Android показывает статус синхронизации в истории.

Каждому измерению назначается постоянная строка. При потере ответа повторная отправка использует ту же строку. При несовпадении содержимого сервер останавливает очередь и отказывается перезаписывать данные.

**Вкладка синхронизации принадлежит приложению:** не сортируйте строки физически, не вставляйте/удаляйте их и не меняйте данные вручную. Для просмотра используйте режимы фильтрации, для изменений и отчётов — копию вкладки. Не направляйте две установки сервера в одну вкладку. Существующий дневник в другой вкладке сохраняется отдельно. Потеря или откат базы требует сверки с Google перед возобновлением синхронизации.

Таблицу можно открыть независимо от телефона и показать врачу. Предоставление врачу доступа выполняется владельцем таблицы. По умолчанию таблица не публикуется.

## Android APK

JDK 17, Android SDK 35, Gradle 8.11.1. Из каталога `android`: `./gradlew :app:assembleDebug`. В Windows: `gradlew.bat :app:assembleDebug`.

Результат: `android/app/build/outputs/apk/debug/app-debug.apk`. Это отладочная сборка; для постоянных обновлений нужен собственный сохранённый ключ подписи. Не добавляйте ключи подписи в Git.

APK не содержит серверного токена, Google-ключа или персональных показателей. Токен вводится на телефоне и хранится в приватных SharedPreferences. Резервное копирование Android отключено. Выбранное старое фото не меняет время измерения автоматически — исправьте его перед сохранением.

Если сети телефона нет, текущие поля сохраняются на телефоне, отправку нужно повторить вручную. После успешного сохранения на VM синхронизация Google продолжится без участия телефона.

## Проверки

Из каталога `server`: `python -m unittest -v`.

Проверка реального снимка без Google: `python check_photo.py --url http://AI_SERVER:11434 --photo /path/to/photo.jpg`. Укажите `--expect 120 80 70`, если эти числа видны на вашем тестовом снимке. Скрипт обращается к существующей Ollama, выводит результат и длительность. Не коммитьте реальные фотографии и результаты измерений.

Перед использованием проверьте несколько снимков при разном освещении, ручную корректировку, сохранение, повторную отправку, отключение Google и восстановление синхронизации. Каждое распознанное число пользователь сверяет с прибором.

## Резервные копии

База — основной источник данных. Не удаляйте volume `journal`, не используйте `docker compose down -v`. Сделайте регулярные резервные копии VM в Proxmox и отдельные копии базы.

```sh
mkdir -p backups
docker compose exec -T api python backup.py > backups/journal.sqlite
```

Команда использует SQLite backup API для согласованного снимка работающей базы. Каталог `backups/` исключён из Git. Проверяйте восстановление на отдельной VM с **отключённым** синхронизатором, чтобы не затронуть Google.

## API

Все маршруты требуют `Authorization: Bearer TOKEN`.

- `GET /health` — доступность API, не проверка Google или модели.
- `POST /recognize` — байты JPEG/PNG, до 10 МБ; ответ содержит три числа и `requires_confirmation`.
- `POST /measurements` — `id` (UUID), `measured_at` (ISO с часовым поясом), `systolic`, `diastolic`, `pulse`, `note`, `confirmed: true`. `saved` означает запись в базе; `synced` — завершённую синхронизацию Google.
- `GET /measurements?limit=50&offset=0` — история, максимум 200 за запрос.
- `GET /statistics?days=30` — количество, арифметические средние и число ожидающих синхронизации. Период — последние N×24 часов.

Приложение ведёт дневник и не интерпретирует показатели.

## Веб-интерфейс и локальный HTTPS

Откройте адрес сервера в браузере и войдите с тем же токеном, что используется в Android. Сессия действует 8 часов; токен не хранится в браузере. Для добавления измерения доступны фото и ручной ввод, затем обязательная проверка чисел.

Без домена можно использовать Caddy с локальным центром сертификации: задайте APP_HOST в .env и запустите docker compose -f compose.yaml -f compose.https.yaml up -d --build. Установите корневой сертификат Caddy на доверенные устройства. Android принимает системные сертификаты и установленные пользователем CA; проверка HTTPS не отключается.

В Android кнопка «Графики и отчёт для врача» открывает тот же веб-интерфейс. Для PDF используйте кнопку «Печать / PDF» в приложении, в браузере — «Отчёт для врача».

GET /dashboard?from=2026-10-01&to=2026-10-28 возвращает все измерения за включительный диапазон дат в часовом поясе TIMEZONE. Статистика — арифметические средние всех измерений; графики не дают медицинской интерпретации.

Доступны вход /auth/login, выход /auth/logout и вход WebView /auth/mobile. Сессии используют HttpOnly, SameSite=Strict и Secure cookie. Изменяющие запросы с cookie требуют CSRF-токен. Android API по-прежнему принимает Bearer-токен.

Скрипт import_history.py импортирует записи с точной датой и временем из разрешённого экспорта Google. Импорт идемпотентен и не дублирует строки в Google. Записи с неточной датой требуют отдельной проверки. Личные экспорты не включаются в Git.

## Светлая и тёмная темы

Веб-интерфейс следует теме устройства при первом открытии. Кнопка темы доступна на странице входа и в верхней панели; выбор сохраняется в браузере. Тёмная палитра применяется к графикам, таблице и формам. Печатная версия всегда светлая.

В Android основной экран также поддерживает светлую и тёмную темы с сохранением выбора. Экран статистики использует переключатель веб-интерфейса. После установки обновлённого APK уже введённые настройки сохраняются.

## Android 0.4: подключение и единый интерфейс

При первом запуске укажите HTTPS-адрес сервера и токен, затем нажмите «Подключиться». Приложение проверяет GET /health с авторизацией и сохраняет настройки только после успешного ответа. При следующих запусках сохранённое подключение проверяется автоматически.

Основной экран Android — тот же веб-дневник с графиками, периодами, журналом и добавлением измерения. В верхней строке отображаются подтверждённая связь, адрес сервера и время последней проверки. Связь проверяется каждые 30 секунд и при возвращении в приложение. При сбое доступна кнопка повторной проверки; ошибки токена, HTTPS-сертификата и сети различаются.

Меню ⋮ открывает настройки подключения, проверку связи и печать PDF. Для фото доступны системная камера и галерея. Выход удаляет сохранённый токен с телефона. Веб-сессия обновляется приложением автоматически. CSV доступен в браузерной версии; в Android используйте печатный отчёт PDF.

Если в старой версии остались поля измерения, они доступны через пункт меню «Запись из предыдущей версии». Приложение не удаляет их при обновлении. Старый экран не используется для обычного входа.

Проверки: :app:testDebugUnitTest проверяет нормализацию безопасного адреса; :app:lintDebug проверяет Android API и ресурсы. Установка поверх предыдущей версии требует той же подписи. Проверку камеры, установки CA и интерфейса на физическом телефоне выполняйте после установки APK.

## Значок браузера и вкладки Google

Иконка вкладки браузера использует тот же знак сердца, что Android-приложение. Новые измерения синхронизируются в SHEET_NAME. Существующие архивные вкладки не дополняются автоматически. В SPREADSHEET_URL можно указать прямую ссылку с gid вкладки измерений, чтобы кнопка сайта открывала её сразу.
